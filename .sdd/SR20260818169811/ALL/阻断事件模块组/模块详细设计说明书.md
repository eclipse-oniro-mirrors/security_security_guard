# ALL-阻断事件降级状态字段-阻断事件模块组 模块详细设计说明书

> TOBE 正式说明书。基于 `.context/详细设计上下文.md` 中的 ASIS 事实（A1–A10、E1–E18）生成；轻量输出模式（小范围变更：单字段扩展 + 两构造点打标 + 测试适配）。

## 1. 需求背景 / 当前 AR 描述

### 1.1 需求与目标

SR20260818169811（免拆分 AR=ALL）：阻断事件 `AuthEvent` 新增降级状态字段 **status**（int32），区分正常阻断事件与降级阻断事件。SA 3524 分流推送时写入：降级路径（`NotifyDegradedClient`）推送的事件 status=1，正常路径（`PushEventsToClients`）推送的事件 status=0。订阅 Client 收到 `OnAuthEvent` 后经 `GetStatus()` 判读事件类型并分化行为。验收口径见 SR-design.md 9.2（TC-001~TC-006）。

## 3. 整体方案

### 3.1 方案概述

在既有 AuthEvent Parcelable 上尾部追加第 5 字段 status（int32，默认 0），SA 侧在分流推送的两条既有路径构造点上分别写入 1 / 保持默认 0，字段经既有手写 IPC 回调（`WriteParcelable`/`ReadParcelable` 全量序列化）自动透出至订阅 Client。不改分流判定、不改聚合/回填/打点链路、不改 IDL 与 BUILD 依赖；序列化实现文件（auth_event.cpp）被 SA/SDK/测试三处无条件编入，单文件改动三侧同时生效。

| 决策编号 | 设计点 | 设计结论 | 设计依据摘要 | 影响范围 | 评审关注点 | 状态 / 待确认说明 |
|---|---|---|---|---|---|---|
| D1 | status 取值常量形态 | 在 auth_event.h 定义 `enum class AuthEventStatus : int32_t { NORMAL = 0, DEGRADED = 1 }`；成员 `status_` 与访问器仍为 int32 形态，枚举仅提供写入/判读符号，不进序列化 | 仓内 AuthStrategy 枚举惯例（auth_strategy.h:21-27）；问题池决策 0=正常/1=降级 | auth_event.h | 枚举值即跨进程契约取值，外仓依赖常量名与取值口径 | 已定稿 |
| D2 | 字段与序列化 | 尾部追加第 5 字段：`int32_t status_ {0}`，`Marshalling` 尾部 `WriteInt32(status_)`、`ReadFromParcel` 尾部 `ReadInt32(status_)` | ASIS A1 定长顺序；用户变更决策（int/GetStatus/SetStatus） | auth_event.h/.cpp | 字段顺序不可调换（尾部追加保证序列化稳定） | 已定稿 |
| D3 | 打标写入点 | NotifyDegradedClient 在 `SetSeqnum(seqnum)` 之后追加 `event.SetStatus(AuthEventStatus::DEGRADED)`；PushEventsToClients 不显式赋值（默认 0），仅补注释 | ASIS A2/A3 构造点行序 | auth_coordinator.cpp 两处 | 降级口必须显式置 1；正常口不得引入冗余赋值 | 已定稿 |
| D4 | 预留注入口 | `AuthEventSubscribeManager::NotifyAuthEvent`（预留口，仅单测调用）不在打标范围，其推送事件 status 恒为默认 0 | ASIS A5/S2 | 无代码改动 | 该口 seqnum=0 无 routing context，"status=0 需回填"语义存在已知歧义，留作限制声明 | 已定稿（声明式） |

## 4. 模块详细方案

### 4.1 AuthEvent 状态字段扩展与分流推送打标

R1/R2/R3/R4/R5 为同一载荷契约的强相关闭环，合并为一个设计问题。

#### 4.1.1 目标与约束

目标：降级路径推送的事件带 status=1、正常路径带 status=0，Client 可判读；序列化往返一致；既有链路（分流判定、聚合、回填、打点、IDL、回调签名）零变更。

影响设计的现状约束（ASIS 摘要）：AuthEvent 现为 4 字段定长顺序序列化（eventId→seqnum→content→metadata，A1）；auth_event.cpp 被 SA/SDK/测试三处 BUILD.gn 无条件编入且符号被 IDL 生成代码引用，改动必须单文件内完成（A7/S1）；OnAuthEvent 为手写 IPC 回调（proxy 以 `WriteParcelable(&event)` 全量装载，A6），新字段随 Parcelable 自动透出，回调签名与命令码零变更。

#### 4.1.2 目标设计

两条既有构造路径的行为保持现状，仅在降级路径增加一次写入：

- 降级路径 `NotifyDegradedClient`（auth_coordinator.cpp:224-244）：构造 `AuthEvent(eventId, content)` → `SetSeqnum(seqnum)` → **新增 `SetStatus(AuthEventStatus::DEGRADED)`** → 经既有手写 proxy 推送。推送失败仅记 SGLOGE 的既有行为不变。
- 正常路径 `PushEventsToClients`（auth_coordinator.cpp:283-314）：构造与 `SetSeqnum` 行为不变，status 保持成员默认初始化 0，不显式赋值；构造点补注释说明"默认 0 = 正常阻断事件"。
- 透出通道零改动：字段经 `WriteParcelable`/`ReadParcelable` 全量序列化自动到达 Client 侧回调（A6），`SetAuthResult` 回填方向不消费该字段。

无核心算法与状态机：字段为单次推送的随附属性，无持久化、无并发共享状态（构造点为栈对象，C5）。不画图——流程与 SR-design.md 2.1 及 context C4 时序一致，无新增参与者。

依赖关系无变化：不新增/修改/移除任何依赖边（含既有 data_collect→libsg_collect_sdk so 链接的存量偏差，本设计不扩大）。

#### 4.1.3 契约与工程落点

**方法 / 函数契约**（auth_event.h，均为头文件内联）：

| 对象 | 变化 | 完整签名 | 异常 / 错误语义 | 关联契约 |
|---|---|---|---|---|
| AuthEvent::GetStatus | 新增 | `int32_t GetStatus() const` | 无异常（返回成员值） | K1 |
| AuthEvent::SetStatus | 新增 | `void SetStatus(int32_t status)` | 无校验（SA 内部写入，Client 只读；非法值不落载荷——仅 SA 两构造点调用） | K1 |
| AuthEvent::Marshalling | 修改 | `bool Marshalling(Parcel &parcel) const override`（尾部追加 `WriteInt32(status_)`） | 写失败返回 false（既有语义） | K2 |
| AuthEvent::ReadFromParcel | 修改 | `bool ReadFromParcel(Parcel &parcel)`（尾部追加 `ReadInt32(status_)`） | 读失败返回 false（既有语义） | K2 |

**常量 / 枚举值**（auth_event.h 内定义）：

| 常量名 | 取值 | 说明 | 关联契约 |
|---|---|---|---|
| `enum class AuthEventStatus : int32_t` NORMAL | 0 | 正常阻断事件（需 400ms 内回填决策） | K1 |
| `enum class AuthEventStatus : int32_t` DEGRADED | 1 | 降级阻断事件（仅通知，不参与聚合回填） | K1 |
| 成员 `int32_t status_` | 默认 0 | 私有成员，默认初始化即 NORMAL | K1 |
| （预留）其余取值 | ≥2 | 未定义，Client 侧应按 NORMAL 处理；本期不赋值 | K1 |

**关键映射规则**（分流 → 打标 → 载荷）：

| 输入条件 | 输出 | 说明 |
|---|---|---|
| clientStatus[] 中该 client IsDegraded()==true → NotifyDegradedClient | 推送事件 status=1 | 与 Provider 声明的降级语义一一对应 |

| 预留口 NotifyAuthEvent（无生产调用） | status=0（默认） | 不在打标范围，见 D4 已知限制 |

**工程落点**（4 个文件）：

| 文件 | 职责 | 变更内容 |

| interfaces/inner_api/collect/include/auth_event/auth_event.h | 契约定义 | 新增枚举 AuthEventStatus、getter/setter 内联、私有成员 `status_ {0}`（追加在 metadata_ 之后） |
| frameworks/common/collect/src/auth_event/auth_event.cpp | 序列化实现 | Marshalling/ReadFromParcel 尾部各追加一段 int32 读写 |

#### 4.1.4 失败语义、风险与验收

失败语义：无新增失败模式——降级推送失败沿用既有"记 SGLOGE 不重试"；序列化读写失败沿用既有 false 返回；status 为 SA 内部写入的标量，无校验/注入面。

| 验证目标 | 覆盖范围 | 输入 / 触发条件 | 预期行为 | 可观察信号 | 关联契约 / 设计点 |
|---|---|---|---|---|---|
| 主路径 | 降级推送打标 | clientStatus[] 标记 IsDegraded 的订阅会话收到推送 | GetStatus()==1；事件不进入聚合（无 promise/分片索引） | Client 回调收到的 event.status；SGLOGI "notify degraded client"（既有日志，含 seqnum） | K1/K2、D3 |
| 边界 | 正常推送默认值 | 未标记 client 收到推送 | GetStatus()==0，正常回填不受影响 | event.status；聚合结果正常回 Provider | K1、D3 |
| 兼容回归 | 序列化往返 | 置 1 序列化读回 1；默认构造读回 0；字段顺序位于 metadata 之后 | parcelable 用例全通过（WriteInt32/ReadInt32 尾部） | auth_event_parcelable_test 断言 | K2、D2 |
| 兼容回归 | 默认产物不变 | security_guard_auth_event_enable=false 构建 | 宏区代码不编入，产物零行为差异 | 构建产物 | S1 |
| 日志观测 | 打标值核对 | 排查推送 status 值与 clientStatus 标记 | 既有分流日志（degraded 计数、notify degraded client）可关联定位 | SGLOGI/SGLOGD | D3 |

可测试性输入（供测试设计消费）：降级/正常/混合分流下 Client 收到的 status 值；序列化往返与默认值；尾部追加顺序；预留口恒 0（声明性，不强制用例）。

已知限制（D4）：预留口 NotifyAuthEvent 推送事件（seqnum=0、无 routing context）status 恒 0，与"status=0 需回填"语义存在理论歧义；该口本期预留未投产（仅单测调用），Client 若回填得既有 NOT_FOUND（auth_coordinator.cpp:739-743 既有语义），不做处理。
